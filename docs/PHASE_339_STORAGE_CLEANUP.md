# 阶段339：项目磁盘清理

本轮不改游戏资源字节、不更新汉化补丁、不生成 ISO 或整盘副本，也不启动游戏。

## 已核实的占用来源

清理前扫描814,190个文件：逻辑大小261,273,511,006字节，按文件标识去重后为152,881,052,032字节。后者仍是唯一文件的内容长度，不是NTFS簇分配/压缩后的精确占用。约101 GiB来自既有硬链接被重复计数。

积累主要来自历史资源候选/回滚演练副本、安装器打包工作目录、CI干净检出/虚拟环境，以及大体积JSON验证报告。

## 实际处理

- 删除50个明确的生成目录，共145,795个文件、7,998,863,121逻辑字节：旧PyInstaller构建/解包目录、已被新版取代的便携安装器、7轮CI的source/venv，以及5份与保留ZIP逐文件匹配的源码展开目录。保留日志、receipt、源文件哈希表、ZIP和重建说明。
- 在两个互相隔离的只读资源清单池内核对33,225条路径，合并23,100条重复资源路径的存储，释放36,830,329,780字节。每个文件路径和SHA256保持；50个被占用/权限拒绝的目标原样保留，没有强制改属性重试。
- 大型历史文本报告仅做逐文件NTFS透明压缩：不更换文件格式、不改路径、不压缩目录本身，处理前后核对SHA256。具体数量和簇分配差额见本轮`text-compression-result.json`。

## 保留及验证

- 两张原版ISO、原版DLC、当前测试入口及candidate/raw-controls、全部runs、账号/配置/存档目录保持。runs内包含账号资料，不按缓存处理。
- 当前安装器`dist/MC2-CN-v1.0.exe`保持SHA256 `811291d8a1bbe463cab215a92842f3062ecc6c5410b2d3fae9097cdaf20cc984`。
- 当前源锁、Disc1/Disc2活动资源、journal链、native工具、最新便携运行时及release-bundle保持。清理前后逐项校验，并从源锁重新生成recipe比较983条资源身份；不以安装器单独存在替代依赖验证。
- `ROLLBACK.sh --test`在另一份小副本上验证原源码恢复、硬链接独立化及NTFS压缩撤销；生产资源保持清理后的状态。已删除的生成缓存按`deletion-plan.json`重建，未为清理再制造整份备份。

本地证据位于`build/phase-339-storage-cleanup/`：`MODIFIED_FILE.json`、`DIFF_FILE.patch`、`VERIFICATION.txt`、`ROLLBACK.sh`，以及完整清单、哈希、逐操作日志。证据含本地资源路径，完整资源不进入Git。

## 后续收尾约定

1. 保留最新可运行测试副本及必要的独立回滚数据；验证通过后淘汰旧打包临时目录和CI source/venv，保留小型receipt、日志、Git提交和源身份清单。
2. 已有压缩源码包并逐文件验证一致时，删展开副本，不同时长期保留二者。
3. 旧资源路径有研究/构建引用时，优先在独立、完整枚举的不可变池中合并存储。原始/回滚池与候选池分开，活动游戏目录、用户数据、工具链和外部硬链接不纳入本次池。
4. `tools.compact_outputs --inventory-prefix NAME`显式允许清单中的顶层名字，仍执行路径、SHA256、受保护扩展名和池内全部硬链接检查。参数可重复；默认candidate/controls模式及`--rollback-only`行为保持。提交清单不是把可变文件变为不可变的替代措施。
5. 共享硬链接资源视为不可变；以后修订先复制到新输出，再原子替换，不就地写共享文件。
6. 对已核对的大型历史文本文件，可执行`compact.exe /C /Q "<absolute-report.json>"`；撤销用`compact.exe /U /Q "<absolute-report.json>"`。只指定文件，不对整个build目录设置继承压缩，不选择游戏二进制或用户数据。
7. 分别报告逻辑大小、硬链接去重长度、实际压缩分配和C盘可用空间。并行操作的free-before/free-after存在时间重叠，不把各操作的磁盘差值相加；使用最终可用空间及各操作自己的文件/分配计数。
