## 可复用技术与合成顺序

语言规则、字形范围、译文、目标对象及预算放在 `locales/zh-Hans/*v9.json`；
通用Python工具不内嵌中文文字或本游戏对象名称。

1. 在哈希核对的阶段329资源副本上运行 `build_font_reface`，仅更新数字。
2. `patch_tagged_fields` 按唯一导出路径/类型/整payload SHA修改21个标量字段。
3. `replace_texture_regions.replace_tiles` 在**当前包**上移植6个商店纹理别名的有限原生块；
   不用全旧纹理包覆盖新字体、手柄布局或阶段329状态文字。
4. 合入带逆向计划的Coalesced/第二盘单个timed-text，以及25张任务图和15段载入片。
5. `compose_revision_layers` 锁定每个before/base、标量计划、原生tile输入及盘归属，
   在全新输出目录重新打开每份候选。拒绝重复资源、可执行文件、未知输入、无变化项、
   路径越界及末级链接输出。候选始终保留，不在其上做回滚测试。

合成输入清单由各部件manifest、保留的before副本和版本化补丁计划生成；
本地 `build/phase-330-gameplay-qa/final-composition-plan.json` 记录确切文件和SHA。
不依赖手工编辑过的中间图。参考执行方式：

```powershell
$p = 'build/phase-330-gameplay-qa/final-composition-plan.json'
python -B -X utf8 -m tools.compose_revision_layers --root . --plan $p `
  --plan-sha256 (Get-FileHash $p -Algorithm SHA256).Hash.ToLower() `
  --output build/phase-330-gameplay-qa/rebuild-check `
  --lzx-library build/lzx/native-verified/ue3_lzx.dll
```

部件构建步骤与输入哈希分别在上述子文档及locale计划中；原始游戏资源由用户提供。
新合成不增加汉化可见范围到未绑定预算的机器字段或编辑器名称。

## 离线验收边界

- 10,416个正文候选中10,411个有可测量结果；5个原盘即有裸反斜杠的字段按ID/源SHA整条保留。
  未证明其控制语义，不把它们计为通过。任何新的未知失败都会让构建返回非零。
- 7,760个未绑定正文宽度的其他字段独立列出；“扫描18,176”不等于“证明全部UI动态布局”。
- 场景1078px/3行是明确的保守静态预算，不宣称已恢复所有原生字幕消费者。
- 实机动画中的自动尺寸、字体缩放、文字显隐、按钮交互及背景重建美观仍需要玩家复测。
- 视频重新编码有损；“保护区保持”指编码前像素，最终视频另做有损误差检测。

## 收尾产物

本地工作目录 `build/phase-330-gameplay-qa` 保存：

- `MODIFIED_FILE.json`：最终候选的盘归属、大小、SHA及变更链。
- `DIFF_FILE.patch`：本轮受版本控制的源码/数据/文档差异，不含完整原始游戏资产。
- `VERIFICATION.txt`：三态确切命令、输入、原样输出、退出码、测试及交付结果。
- `ROLLBACK.sh`：只在隔离副本恢复原字节并复测，最终候选保持改后状态。

测试副本沿用原路径，使用现有hash-guarded增量工具；TOC只重算实际变化资源的尺寸。
不创建额外ISO或完整游戏副本，保留原盘、配置、存档、runs、active packet依赖及回滚证据。
完整交付身份以本轮 `VERIFICATION.txt` 和刷新工具的回读报告为准。
